Tidy Data and Data Organization

Organize analytical data so each variable has a column, each observation has a row, and each type of observational unit has a table. Learn why this reduces manual work and errors.

◷ 45 minBeginner

What you will learn

  • State the core tidy-data principles.
  • Recognize common untidy layouts.
  • Reshape wide repeated measures into long form.
  • Separate multiple observational units.
01

Tidy structure

A tidy analytical table uses one column per variable, one row per observation, and one table per observational unit. This convention makes operations predictable: filter rows, select columns, group by categories, and summarize numerical fields.

02

Common untidy patterns

Common problems include variable names stored as values in headers, multiple variables combined in one column, one observation spread across several rows, repeated blocks, and several units mixed in one table. Presentation reports often need reshaping before analysis.

03

Long and wide transformations

Pivoting longer moves repeated column headers into a variable; pivoting wider spreads category values into columns for a specific presentation or matrix. Neither shape is universally best, but tidy long form is often a reliable storage and analysis base.

04

Separate entities and events

Customers, orders, products, and order lines are different observational units. Repeating customer details on every order may be practical in a flat file, but relational analysis should understand keys and relationships to avoid double counting.

Vocabulary

Key terms

Tidy data

A consistent structure with variables in columns and observations in rows.

Pivot longer

Transform repeated measure columns into variable-value rows.

Pivot wider

Spread category values into separate columns.

Observational unit

The entity or event represented by one row.

Example

Reshaping monthly branch sales

A sheet has columns branch, Jan_sales, Feb_sales, and Mar_sales.

  1. 1

    The repeated month names are values stored in column headers.

  2. 2

    Keep branch as an identifier variable.

  3. 3

    Create a month column.

  4. 4

    Create a sales column.

  5. 5

    Each branch-month becomes one observation.

Conclusion

The long table can accept new months without changing the analysis formula or chart design.
