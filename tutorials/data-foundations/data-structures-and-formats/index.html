Structured, Semi-structured, and Unstructured Data

Data comes in tables, tagged records, documents, images, audio, and logs. Learn how structure affects storage, validation, and analytical preparation.

◷ 40 minBeginner
ObjectivesLearnExampleTry itExercisesSummary
Start here

What you will learn

  • Distinguish structured, semi-structured, and unstructured data.
  • Recognize common file formats.
  • Explain why schema matters.
  • Choose a usable format for an analytical task.
01

Structured data

Structured data follows an explicit schema, commonly rows and columns with defined field types. Relational tables and well-formed CSV files are typical examples. Structure makes filtering, joining, validation, and aggregation straightforward.

02

Semi-structured data

Semi-structured data contains labels or nested organization but does not require a fixed rectangular table. JSON, XML, application events, and many API responses are examples. Analysts often flatten nested fields or extract repeated records before tabular analysis.

03

Unstructured data

Documents, free text, images, audio, and video do not arrive as predefined analytical columns. They still contain information, but require coding, text processing, annotation, image analysis, or metadata extraction before many standard analyses.

04

Formats are not the same as meaning

CSV describes storage, not the quality or meaning of the data. A CSV can still mix observations, contain invalid dates, or omit definitions. JSON can be highly regular. Always inspect schema, semantics, and provenance—not only the file extension.

Vocabulary

Key terms

Schema

Rules describing fields, types, constraints, and relationships.

CSV

A plain-text format for delimited tabular records.

JSON

A text format for objects, arrays, and nested key-value data.

Metadata

Information describing data, such as source, date, field meaning, or file properties.

Example

Website activity data

An organization has a users table, JSON click events, and free-text support messages.

  1. 1

    The users table is structured.

  2. 2

    The nested event records are semi-structured.

  3. 3

    Support message bodies are unstructured text.

  4. 4

    Use IDs and timestamps to connect sources only when definitions and privacy rules permit.

  5. 5

    Transform each source according to its structure before analysis.

Conclusion

Different structures can support one question, but each requires different preparation and governance.

Summary

What to remember

  • Structured data follows an explicit schema.
  • Semi-structured data has tags or nested organization.
  • Unstructured data requires additional extraction or coding.
  • File format does not guarantee quality.
