Rows, Columns, Tables, and Datasets

Understand how analytical data is organized into rectangular tables, related tables, files, and datasets—and why structure determines what questions can be answered.

◷ 40 minBeginner

What you will learn

  • Explain rows, columns, tables, and datasets.
  • Recognize a well-structured analytical table.
  • Distinguish a single table from a multi-table dataset.
  • Identify common structural problems.
01

Rectangular tables

Most analytics begins with a rectangular table: rows are observations and columns are variables. A header names each variable, and each column should have a consistent meaning and data type. Decorative titles, merged cells, subtotal rows, and multiple headers make machine analysis difficult.

02

Dataset

A dataset is a purposeful collection of related data. It may be one CSV file or several related tables such as customers, orders, and products. A data dictionary, source notes, and relationships are part of understanding the dataset even if they are stored separately.

03

Wide and long structures

Wide data stores repeated measures in separate columns, such as sales_jan and sales_feb. Long data stores period as a variable and each measurement as a row. Long structures are often easier for filtering, grouping, charting, and time-based analysis.

Vocabulary

Key terms

Table

A rectangular arrangement of rows and columns.

Dataset

A collection of related data prepared for a purpose.

Schema

The documented structure: fields, types, rules, and relationships.

Data dictionary

A reference that defines fields, units, codes, and valid values.

Example

Repairing a spreadsheet export

A sales sheet has a title in row 1, blank rows, merged headers, monthly columns, and a Total row.

  1. 1

    Remove presentation-only rows from the analytical table.

  2. 2

    Create one header row with unique names.

  3. 3

    Keep one observation per row.

  4. 4

    Move monthly column names into a month variable when repeated analysis is needed.

  5. 5

    Calculate totals in analysis rather than storing subtotal rows inside raw data.

Conclusion

A clean table is easier to validate, combine, filter, and reuse across Excel, SQL, Power BI, and Python.

Summary

What to remember

  • A clean table has one header row and consistent columns.
  • A dataset may contain multiple related tables.
  • Metadata and dictionaries explain structure.
  • Long data often supports reusable analysis.
