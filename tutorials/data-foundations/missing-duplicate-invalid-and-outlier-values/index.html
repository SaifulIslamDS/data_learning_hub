Missing, Duplicate, Invalid, and Outlier Values

Learn four common data issues, why they are not interchangeable, and how to investigate before deleting, replacing, or correcting records.

◷ 50 minBeginner
ObjectivesLearnExampleTry itExercisesSummary
Start here

What you will learn

  • Differentiate missing, duplicate, invalid, and outlier values.
  • Investigate causes before treatment.
  • Choose defensible actions.
  • Document changes and sensitivity.
01

Missing values

A missing value means no usable value is recorded, but causes differ: not collected, not applicable, refused, lost, or system failure. Blank, zero, “N/A,” and “unknown” are not automatically equivalent. Preserve reason codes when possible.

02

Duplicates

Exact duplicate rows may result from repeated imports, but similar rows can be legitimate repeated events. Define a business key and time rule before removing duplicates. A customer can place two identical orders; they are not duplicates if order IDs differ.

03

Invalid values

Invalid values violate a declared rule: impossible dates, negative quantity when returns use a separate flag, or category codes outside the dictionary. Rules must reflect domain reality; a rare value is not invalid merely because it is unusual.

04

Outliers

An outlier is unusually distant from other values or an expected pattern. It may be an error, a rare but real event, or the most important observation. Investigate source, unit, timing, and context before exclusion. Compare results with and without influential points when appropriate.

Vocabulary

Key terms

Missingness

The pattern and reason values are absent.

Business key

Fields that uniquely identify an entity or event in context.

Invalid value

A value that violates a documented rule.

Outlier

An observation unusually distant from a distribution or model pattern.

Example

Cleaning order records responsibly

The file has blank customer ages, repeated order IDs, a negative quantity, and one exceptionally large order.

  1. 1

    Determine whether age is required and why it is missing.

  2. 2

    Use order_id plus line_id to confirm true duplicates.

  3. 3

    Check whether negative quantity represents a return.

  4. 4

    Verify the large order against source documents.

  5. 5

    Record every treatment and compare key results before and after changes.

Conclusion

Cleaning is evidence-based correction and documentation—not automatic deletion of inconvenient records.

What to remember

  • Different issues require different treatments.
  • Investigate causes before changing data.
  • Outliers may be errors or valuable real events.
  • Document every transformation.
