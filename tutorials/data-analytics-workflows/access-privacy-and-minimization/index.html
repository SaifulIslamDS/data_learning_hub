Data Access, Privacy, and Minimization

01

What Data Access, Privacy, and Minimization means

Data minimization means using only fields and records necessary for the stated purpose. Access should follow authorization, privacy, confidentiality, and retention requirements even when the dataset is technically available. In a complete analytics project, this stage must leave visible evidence that another reviewer can inspect. The analyst should state the decision, data grain, definitions, assumptions, and expected output rather than relying on memory or undocumented discussion.

02

How an analyst applies it

Remove direct identifiers from practice extracts and document why each sensitive field is required before analysis. In the customer retention case, the analyst connects this step to cohort retention, repeat purchases, and churn signals. The output is recorded in the project charter, data dictionary, analysis plan, validation log, report, or repository so it can be reused across Excel, SQL, Power BI, and Python.

03

Controls, mistakes, and completion evidence

Common failures include beginning with a preferred tool, changing definitions mid-project, omitting excluded records, accepting unreconciled totals, and writing conclusions that exceed the evidence. Completion should be demonstrated with a named artifact, an owner, a validation result, and a documented limitation—not only a verbal claim that the step is finished.

Vocabulary

Key terms

Personal data

Information relating to an identifiable person.

Minimization

Limiting data to what is necessary.

Authorization

Permission to access or use data.

Retention

Period for keeping data and outputs.
